# SPECFEM3D_GLOBE to MTUQ Green's Functions Pre-Processor

This repository contains a modular Python pipeline designed to post-process raw seismic wavefield simulations generated by `SPECFEM3D_GLOBE` into a Green's Functions (GFs) database formatted specifically for Moment Tensor Uncertainty Quantification (`MTUQ`).

### 1. `PROCESS_GFs/`
This contains the scripts and configuration files necessary to process the SPECFEM3D_GLOBE simulations.
*   **`process_mtuq_gfs.py`**: The core execution engine.
*   **`config_*.json`**: The configuration files used to pass variables (event IDs, velocity models, processor partitions, and depths).

### 2. `SIMULATIONS/`
This directory contains the output from the `SPECFEM3D_GLOBE` solver. It is structured by velocity model, processor partition, event ID, and depth.
*   **`SOLVER_REPO/`**: Contains the raw `*sem.sac` seismograms organized into the six elementary moment tensor components (`MPP`, `MRP`, `MRR`, `MRT`, `MTP`, `MTT`). The script extracts necessary metadata (event coordinates and exact scaling factors) directly from the `CMTSOLUTION` and `STATIONS` files located within these subdirectories.

*   **`DATABASES_REPO/` [IMPORTANT NOTICE]**: In this repository, the `DATABASES_REPO` directory is included strictly for  reference and is **empty**. This directory is intended to store the massive partitioned mesh databases (the `GLL` files) required to run the actual wavefield simulations. Due to GitHub storage constraints, these files are not hosted here.
    *   *for further information contact Félix Rodríguez-Cardozo directly at:* [frodriguezcardozo@gmail.com](mailto:frodriguezcardozo@gmail.com).

### 3. `READY_GFs/`
**Note: This directory does not exist in the initial repository clone.** 
It is dynamically generated by the script during execution. The pipeline will aggregate all processed SAC files into a structure organized by depth (e.g., `READY_GFs/[velocity_model]/[processors]/[event_id]/[depth]/`), matching the exact formatting conventions required by `MTUQ`.

## Usage
**1. Configure the JSON parameters**
Create or modify a JSON configuration file (e.g., `config.json`) in the `PROCESS_GFs/` directory to match your simulation structure:
```json
{
    "event_id": "20171201023244",
    "velocity_model": "ME-MEAD20",
    "processors": "256_PROC",
    "depths": [1, 2, 3, 4]
}
